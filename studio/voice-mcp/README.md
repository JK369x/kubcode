# Voice MCP — local, opt-in prototype

Uses the official `@modelcontextprotocol/sdk` over **stdio only**; no listener or client registration is created. In this folder run `npm ci --ignore-scripts`, `npm test`, or `node server.mjs` from a compatible MCP client. Do not print credentials to chat. Client configuration is intentionally not installed automatically; a user must choose and configure their client later.

Tools: `list_voice_providers`, `list_voice_models`, `list_voices`, `prepare_voice_job`, `voice_job_status`, `cancel_voice_job`, `inspect_shot_plan`. Jobs are in memory and disappear on restart; request ID is idempotent per server process, different input with the same ID is rejected. Preparation never generates audio, spends money, or reaches a provider. There is **no MCP synthesis tool**, queue or artifact tool yet. The public voice catalog is deliberately partial and not account-verified; no fake ElevenLabs voices or cost values. The inspect tool uses an allowlisted built shot-plan slug and returns shot IDs and existing manually assigned timing. This is read-only integration, not automatic narration or retiming.

`adapters.mjs` implements provider request shapes for Google Cloud TTS and ElevenLabs and accepts injectable transport/signal; only mock HTTP responses have been tested. `synthesizeForFutureIntegration` is not exposed through MCP or UI. Its `approval` boolean is an internal development guard, **not** a trusted user consent mechanism. Before exposing it, implement a real user-facing quote/approval bound to exact provider, voice, text, settings and price, a safe durable job/artifact store, verified credentials and permissions, and explicit retry/cancellation semantics. No silent paid/free fallback. Estimates are currently unknown, not zero. Provider errors are sanitized and never automatically retried. The optional discovery adapter is also not exposed or called live. Language/model support varies; for ElevenLabs, `eleven_v3` is documented for Thai, but account availability must be verified.

Google requires Cloud TTS enabled, an authorized OAuth access token and billing setup; ElevenLabs requires its own API key and eligible voice/model access. Credentials must stay in a private local process, not browser or this repository. MCP only reports `present_unverified` / `not_configured` for exact `GOOGLE_TTS_ACCESS_TOKEN` and `ELEVENLABS_API_KEY` environment variables; it never prints values. No account, token or credential was created. The local Thai narrator needs its existing MLX setup and is not started by this server. Provider-specific actual audio settings, pricing, preview samples and account discovery require a later live integration; the mock Voice Lab makes no live-voice claim.

Sources: user-requested [Genhaha guide](https://videos.genhaha.com/guide) (provider choices, preview and confirmation workflow; no proprietary code/assets copied); [Google voices](https://docs.cloud.google.com/text-to-speech/docs/reference/rest/v1/voices/list) and [synthesize](https://docs.cloud.google.com/text-to-speech/docs/reference/rest/v1/text/synthesize); [ElevenLabs voices](https://elevenlabs.io/docs/api-reference/voices/search), [models](https://elevenlabs.io/docs/overview/models), [synthesize](https://elevenlabs.io/docs/api-reference/text-to-speech/convert); [MCP TypeScript SDK](https://ts.sdk.modelcontextprotocol.io/server.html). The user's downloaded Genhaha license permits use while prohibiting repackaging its files as our own product; this implementation is independent.
